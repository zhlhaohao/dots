# 2. 九宫格配置存 filesDir 并依赖 Android Auto Backup 恢复

日期：2026-09-18
状态：已接受

## 背景

Dashboard 改为九宫格启动台（每格对应一个 WebView URL）。需求：格子可长按编辑、拖拽排序、一键恢复默认；配置保存到手机本地，**卸载重装 APK 后配置不丢**，且全程不需要重新编译或重装前手动导出。

候选存储位置：

1. **App `filesDir`（内部存储）**：零权限、无用户可见文件；但卸载即清除，重装恢复依赖系统备份机制。
2. **公共 Downloads 目录（MediaStore 写入）**：卸载重装必然保留，且用户可用文件管理器直接改 JSON；需处理用户手改坏 JSON 的容错与权限适配（API 29 前后行为不同）。
3. **filesDir + 手动导入导出**：最稳妥但多一套导入 UI，且「手动导出」违背「无需重装前手动操作」的需求。

事实核对：Manifest 已有 `android:allowBackup="true"`，minSdk 23（Android 6.0+），Auto Backup 默认备份 `filesDir`，无需新增任何权限或代码开关。

## 决策

九宫格配置存 `filesDir/grid_items.json`（用户配置），assets 内置一份出厂配置（九格初始布局）。首次启动把出厂配置拷贝为用户配置，之后一切编辑读写用户配置。卸载重装后的恢复依赖 Android Auto Backup。

## 后果

- 正面：零额外权限、零新代码路径（备份机制系统托管）；JSON 原生 `org.json` 即可解析；符合「编辑即生效、免重编译」需求。
- 负面：恢复依赖设备备份服务可用性——无 Google 服务的国产 ROM 上 Auto Backup 可能不生效，重装后回到出厂配置（编辑内容丢失）。
- 缓解：若未来此风险成为现实，可低成本叠加「导出到 Downloads」备份入口，不需要推翻本决策（主存位置不变）。

## 备注

- 出厂配置含演示页入口，保证 JSBridge 演示链路在九宫格改造后仍可达。
- 需要容错：用户配置 JSON 解析失败时回退出厂配置（不崩溃）。
